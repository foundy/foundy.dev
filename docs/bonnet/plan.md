# bonnet v2 — 최종 계획 ("Live Dye")

> 2026-10-09 · v0 초안 → 1라운드(Codex 별도 세션 + 독립 서브에이전트 CD/WebGL) → v1 → 2라운드(동일 검토자) → **최종**
> 원문: `plan-v0.md`, `plan-v1.md`, `review-r1-codex.md`, `review-r1-cd.md`, `review-r2-codex.md`, `review-r2-cd.md`
> 2라운드 점수: Codex 7.5 / CD 7.5 → 아래 §2의 "전역 파면"과 §4 S3 "한 코 → 거대 구조"가 9점 목표의 마지막 한 수.

## 0. 확정 사실 (직접 검증)
- 20장 = 5색 × 4각도.
- **red·green·yellow·sky 4색(625×625)은 각도별로 사실상 픽셀 정합** — 아기·포즈·배경·보닛 실루엣 동일, 색과 미세 스티치 텍스처만 다름 (차분 이미지 확인).
- **ivory(1122×1402)는 별도 생성본** — 얼굴형·눈·입·끈 매듭·러플·보닛 스티치가 모두 다름 (나란히 비교 확인). 정합 불가.
- 625px는 390pt 폭 히어로에서 약 1.6배 샘플 밀도.

## 1. 컨셉
> **"사진 속 아기는 그대로인데, 손가락이 지나가는 곳마다 보닛이 한 코씩 다른 실로 다시 떠지고 — 그 파도가 화면 전체를 물들인다."**

- 덱 = 한 장의 사진, 다섯 가지 실. 스와이프 = 재염색.
- 실(thread) = 사진 *바깥* 공간 언어(프레임·레일·전환 구조).
- 화려함의 두 축: ① 사진 속 제품만 살아 움직이는 비현실감 + 페이지 전체가 같은 파면으로 물드는 **하나의 물리적 사건**, ② 상세 진입 시 **작은 한 코가 거대한 구조로** 커지는 스케일 반전.

### 얼굴 보호 (하드 제약)
1. 사진 전체엔 이동·균일 스케일·크롭·opacity·전역 밝기 ±8%만. 비균일 스케일 0, 회전 ±2°.
2. 재질 효과는 보닛·끈 마스크 안에서만. 페더는 **적응형**(두꺼운 경계 6px, 얇은 끈 1–2px).
3. 아기 대상 해체·파티클·녹아내림 금지. 얼굴 위 블러·색수차 금지.
4. QA: 모든 효과 최대값 프레임 육안 체크리스트.

## 2. 시그니처: 전역 염색 파면 (Global Dye Wavefront)
- 손가락(또는 탭한 레일/스와치) 위치를 원점으로 하는 **단 하나의 거리장 파면** `front(t) = 원점으로부터의 거리 ≤ R(p)`.
- 파면이 순서대로 지나가며 물들임: **보닛 코 셀 → 사진 프레임 실 → 색 레일 실타래 → 배경 스캘럽 → DOM 타이포 액센트·버튼(`--dye` CSS 변수)**. DOM 요소는 요소 중심이 파면에 닿는 순간 전환(같은 p, 같은 거리 함수를 JS에서 계산).
- 파면 앞 2px 밝은 이음선(seam). 커밋 순간 이음선이 가속해 화면 끝까지 쓸고 나감(160ms, 오버슈트 없음).
- 데이터 모델: `dye = { from, to, origin{x,y}, p }` 하나를 GL 유니폼과 DOM이 공유. **M1부터 이 구조로 시작**(나중에 붙이면 재작성).

## 3. 자산 파이프라인 (빌드 타임 스크립트, 산출물 커밋)
1. **기준 프레임 = 625 세트, 1:1.** ivory 원본은 사용하지 않음.
2. **ivory 합성**: 기준 사진(가장 밝은 yellow 또는 sky)의 보닛 마스크 영역만 LAB 재색(채도↓·명도↑, 크림 톤)으로 ivory 4장 생성. 데모 샘플이므로 허용(사이트에 "demo" 표기 유지).
3. **마스크**: 4색(+합성 ivory) 픽셀 분산 → 1차 마스크 → 레이스 구멍 hole-fill → **SAM2 또는 수동 보정 필수**(끈·옷 경계, 구멍 속 피부/머리카락) → 각도당 공통 마스크 + 색별 경계 보정 → 적응형 페더. 20장 경계 검수 후 공유 여부 확정.
4. **코 셀 맵**: 정수리 기준 **행 거리장(스캘럽 행) × 각도 섹터**의 극좌표 셀, 각도별 4장 수동 가이드. ID는 무손실 1채널·nearest 샘플링, 전파 임계값은 별도 채널/데이터.
5. **해상도**: 기본은 원본 625. 2x 업스케일은 **선택 실험**(4색 동일 모델·동일 타일 설정) — M0b에서 iPhone 실측 비교 후 채택 여부 결정. 섬유 매크로 루페는 보류(환각 확대 위험).
6. 색 관리: 모든 출력 sRGB 변환·ICC 제거. 1x/2x WebP, 마스크·셀은 무손실.

## 4. 스토리보드 (모바일 390×844 기준)

### S0 인트로 (후순위, ≤900ms, 세션당 1회)
첫 사진 즉시 표시(LCP) → 보닛만 회색 실루엣에서 정수리부터 행 순서로 코가 채워짐 → 하단에서 실 한 가닥이 레일로 감김. 첫 입력 시 120ms 내 종료, 입력은 원래 동작으로 전달.

### S1 덱 휴지
단일 스테이지(1:1 사진, 화면 폭 ~88%, 둥근 모서리) + 하단 **색 레일**(5개 실타래 버튼, 현재 색 실타래에서 실 한 가닥이 사진 프레임으로 이어짐). 휴지 모션 1개(4초 주기 보닛 마스크 내 섬유 쉬머, 후순위). 배경 저채도 현재 색 톤.

### S2 스와이프 = Live Dye + 전역 파면 (핵심)
- 가로 드래그 p = dx/폭, **첫 픽셀부터 1:1**(slop 이전 이동도 반영).
- 파면 원점 = 터치 시작점. 보닛 코가 셀 단위로 다음 색 사진으로 뒤집힘 → 프레임 실 → 레일 → 배경 → DOM `--dye` 순.
- 장력은 실에만(레일 실 가닥이 다음 실타래로 당겨짐).
- 커밋: 부호 있는 속도 > 0.3px/ms(방향 일치) 또는 |p| > 0.5 → 다음 색. 임계 감쇠 스프링(오버슈트 없음). **한 제스처 = 한 색**(2장 건너뛰기 없음, 점프는 레일 탭).
- 버튼/키/레일 탭: p 0→1 **220ms** easeOutExpo, 레일 탭은 그 실타래 위치가 원점. 연타는 큐 없이 남은 진행 즉시 완료 후 다음 시작.

### S3 덱 → 상세 (대표 장면, ~650ms, 가역)
"한 코가 공간의 크기를 바꾸는 순간":
- 0–80ms 탭 다운: 사진 scale 0.985 프레스. 선택 색 보닛 가장자리의 **한 코에 빛이 모임**.
- 80–360ms: 그 코에서 **실 한 가닥**이 프레임 밖으로 뽑혀 화면 가장자리를 훑음. 동시에 사진 rect가 덱 슬롯 → 히어로 앵커로 확장(모서리 28→0, affine). 앵커 rect는 **매 프레임 재측정**(조기 스크롤·주소창 대응).
- 300–600ms: 실이 히어로 **뒤** 배경에서 **거대한 쉘 고리 3개를 순차로 당겨 세움** → 마지막 고리가 팽팽해지는 순간 배경 조명과 제목이 함께 정착.
- 200–480ms: 제목 DOM FLIP, 본문 줄 단위 리빌. **본문은 나타나는 즉시 스크롤 가능.**
- 정착 후: 배경 쉘 구조를 **미리 구운 정적 이미지(WebP/SVG)로 DOM 교체, GL 휴면**.
- 전환 중 사용자가 스크롤을 시작하면 → 즉시 최종 상태로 정착(DOM 핸드오프) 후 스크롤 진행.
- 렌더링: 실 = 인스턴스드 리본 메시(3차 베지어를 정점 셰이더에서 평가, 64세그 × 2정점, 전경 4–8가닥, 앞 10–16px·뒤 4–6px), 가짜 원통 노멀 램버트+림, 연사 줄무늬, (3,6)px 오프셋 그림자 알파 0.18(블러 없음), 그리는 순서로 가림. 배경 고리 = 0.5x 해상도 풀스크린 SDF 스캘럽(같은 튜브 셰이딩). **별도 연출 프로토타입으로 먼저 검증.**

### S4 상세 (DOM, window 네이티브 스크롤)
- 히어로 `<img>` + 히어로 요소 **안의 in-flow `<canvas>`**(position:absolute, 히어로와 함께 네이티브 스크롤; fixed 오버레이 금지).
- 색 변경: 스와치 탭 → in-flow 캔버스에서 Live Dye 파면(450ms, 원점 = 스와치 방향) + DOM `--dye` 파면 → 끝나면 `<img>` 교체 후 캔버스 숨김.
- 각도: 점/썸네일/히어로 가로 스와이프(`touch-action: pan-y pinch-zoom`)로 선명한 방향성 와이프(180ms).
- 섹션 SVG 라인 드로잉 하나만.

### S5 상세 → 덱 (≤400ms)
닫기 버튼/Esc/Back. 스크롤 강제 이동 금지. 히어로가 보이면 현재 rect에서 GL 사진 스폰 → 덱 슬롯으로 수축, 배경 고리가 실 한 가닥으로 감겨 레일로 회수. 히어로가 화면 밖이면 본문 페이드 + 덱 사진 제자리 페이드-스케일 인. 색이 바뀌었으면 그 색으로 복귀.

### S6 마이크로
버튼 프레스 scale 0.96/80ms, 복원 120ms. 큰 장력 해소는 S2 커밋에만.

### S7 Inspect 미니 (후순위)
마스크·코 셀·파면 거리장·p를 단계적으로 시각화(메인 사이트 Inspect 언어).

### 삭제 확정
풀다운 닫기, 깊이맵 2.5D 회전, 원통 곡면 덱, 사진 스트레치·실 풀림 해체, 햅틱, 사운드, 자이로, 호흡 scale, 2장 건너뛰기.

## 5. 아키텍처 & 계약
- 하위 프로젝트 `bonnet/`(독립 Vite + TS, 추후 저장소 분리). 기존 v1 코드는 폐기하고 새로 작성.
- 렌더러 **raw WebGL2**. 메인 사이트 렌더러의 휴면/visibility/context-loss 루프 패턴만 참고(depth·float target 요구사항은 그대로 복사하지 않음; 필요 기능만 확인 후 사용).
- 캔버스: 덱/전환용 1개(`pointer-events:none`, `lvh` 고정, DPR ≤ 2) + 상세 히어로 in-flow 1개(필요 시 같은 컨텍스트 reparent 검토).
- **핸드오프 계약**: 동일 이미지·UV·크롭 수학(object-fit·반경·서브픽셀, rect `Math.round` + DPR 스냅), sRGB/ICC 제거, `UNPACK_COLORSPACE_CONVERSION_WEBGL=NONE`, premultiplied 설정 통일, `img.decode()` 선행, **DOM 표시 → 다음 rAF에 GL 숨김(1프레임 겹침)**.
- **상태 분리 & 동시 입력 규칙**(표로 명세, 구현 전 확정): 페이지(덱/열림중/상세/닫힘중), 덱 색, 각도, 염색 진행. 색/각도/열기/Back 동시 입력 시 우선순위; 텍스처 미준비 시(로딩 링 없이) 이전 색 유지 후 준비되면 파면 재생 또는 크로스페이드 폴백; 애니메이션 완료가 버튼·스크롤 활성화 조건이 되지 않음.
- **입력 규칙**: `<button>` click 단일 경로, 전역 클릭 차단 금지(ghost click 억제는 해당 드래그의 그 요소 1회), 제스처 면 사전 `touch-action: pan-y pinch-zoom`, 버튼 시작 입력은 제스처 제외, 본문 `touchmove.preventDefault()` 금지, `pointercancel`/`lostpointercapture`/visibilitychange 정리.
- **텍스처 수명**: 덱 = 현재 각도의 5색 + 마스크·셀. 상세 = 현재 색 4각도 + (색 변경 대비) 현재 각도의 이웃 색 미리 준비. 사용 끝난 ImageBitmap close. context lost → DOM 폴백.
- 폴백(GL 불가/reduced-motion): 같은 UI, 색 전환 = CSS `mask-image` 와이프 또는 크로스페이드, `--dye` 파면은 유지(시간 단축). 접근성·reduced-motion은 **M0부터**.

## 6. 검증
- **실기기 게이트(필수)**: 매 마일스톤 iPhone 시나리오 — 스와이프 직후 50/100/200ms 버튼 탭, 대각선 미세 이동 후 탭, 빠른 방향 반전, 열기 도중 스크롤, 히어로/본문 각각에서 스크롤 시작, 관성 스크롤 중 색 변경, 주소창 확장/축소, 회전, 핀치줌, Back/Forward, 잠금 복귀, 5–10분 반복. 화면 녹화 제출.
- `?debug` 오버레이: fps, 33ms 초과 비율, 최장 멈춤, 입력→첫 반응 ms, 이벤트·상태 로그.
- 자동 테스트는 보조: 실제 터치 스와이프로 스크롤 검증(`scrollTop` 직접 설정 금지), 가상 타임스탬프 의존 금지.
- 얼굴 QA 체크리스트, 핸드오프 튐 프레임 비교(GL 마지막 프레임 vs DOM 첫 프레임 차분).

## 7. 마일스톤
- **M0a — 입력 골격 (DOM만)**: 덱/레일/버튼/상세/window 스크롤/Back, 접근성·reduced-motion 포함 → **iPhone에서 원본 v20.0.15와 나란히 비교, 원본 이상이어야 통과.**
- **M0b — 자산 타당성 (병행)**: 한 각도(front) 완성본: 마스크(보정 포함)·극좌표 셀 맵·합성 ivory·(선택) 2x 업스케일 비교 → 정적 Live Dye 데모 페이지로 iPhone 실제 크기 육안 확인.
- **M1 — Live Dye + 전역 파면** (S2, DOM `--dye` 포함) → iPhone 게이트 + 영상.
- **M2 — S3 연출 프로토타입** (단독 페이지에서 "한 코 → 거대 고리" 검증) → 통과 시 S3/S5 통합 + 핸드오프 계약 → iPhone 게이트 + 영상.
- **M3 — S4** (in-flow 캔버스 색 변경, 각도 와이프) + 나머지 3각도 자산 → iPhone 게이트.
- **M4 — 후순위**: S0 인트로, S7 Inspect, 쉬머, 데스크톱 패럴랙스 + 성능 패스 → 배포.

각 마일스톤은 사용자 iPhone 확인을 받은 뒤 다음으로 진행.

## 8. 사용자 결정이 필요한 것
1. ivory를 **합성(다른 사진의 보닛만 크림색으로 재색)** 으로 만드는 것에 동의하는가? (대안: ivory 제외 4색만 / ivory는 다른 아기 사진이라 전환 시 크로스페이드 예외 허용)
2. 진행 방식: 마일스톤마다 iPhone 확인 후 다음 단계 — 동의하는가?
