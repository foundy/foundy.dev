## 1. 자산 사실 확인 (직접 검증)
- 20장 = 5색 × 4각도. **같은 각도의 사진은 아기·포즈·배경이 동일하고 보닛 색만 다름** (red/green front 차분 이미지에서 보닛·끈만 남고 얼굴은 미세 윤곽만).
- 해상도 불균일: ivory(beige) 4장 **1122×1402(4:5)**, 나머지 16장 **625×625(1:1)**. → 정합·크롭·업스케일 파이프라인 필수.

## 2. 컨셉: "Live Dye" — 한 아기, 다섯 가지 실
한 문장: **"사진 속 아기는 그대로인데, 손가락이 지나가는 곳마다 보닛이 한 코씩 다른 실로 다시 떠진다."**
- 덱은 "카드 5장"이 아니라 **한 장의 사진, 5가지 실**. 스와이프 = 재염색.
- 실(thread)은 사진 바깥의 공간 언어: 프레임, 색 레일, 인디케이터, 전환 구조를 잇는 한 가닥.
- 화려함의 원천: (1) 사진 속 제품 자체가 살아 움직이는 비현실감, (2) 전환 순간 실이 화면 전체 구조로 확장되는 **스케일 반전**.

### 얼굴 보호 규칙 (하드 제약)
1. 사진 전체에는 이동·균일 스케일·크롭·opacity·전역 밝기 ±8%만. 비균일 스케일 0, 회전 ±2° 이내.
2. 모든 재질 효과(염색 경계, 섬유 쉬머, 매크로)는 **보닛·끈 마스크 안에서만**, 가장자리 6px 페더.
3. 아기를 대상으로 한 해체·파티클화·녹아내림 금지. 퇴장은 페이드/크롭.
4. 얼굴 위 블러·색수차 금지.
5. QA: 모든 효과의 최대값 프레임 캡처 → "아기가 이상해 보이는가" 육안 체크리스트.

## 3. 자산 파이프라인 (빌드 타임, 커밋되는 산출물)
1. **정합**: 각 각도별로 ivory(4:5 고해상) 기준, 나머지 4색을 특징점/ECC 정합(OpenCV) → 동일 프레임(4:5) 크롭. 잔여 오차 측정(얼굴 영역 평균 차이) 리포트.
2. **업스케일**: 625px 계열을 1122×1402 수준으로(Real-ESRGAN 등 로컬 실행). 품질 육안 확인. 불가 시 표시 크기 상한으로 레이아웃 조정.
3. **보닛·끈 마스크**: 같은 각도 5색의 픽셀별 색 분산/색상 차이로 1차 마스크 → 모폴로지 정리 → (필요시 SAM2로 보정) → 6px 페더. 각도당 1장(4장)만 필요할 수 있음(정합 후 공유) — 검증.
4. **코 셀 맵(stitch cell)**: 마스크 내부를 쉘 스티치 행/코 단위 셀로 분할한 ID 텍스처(절차적 Voronoi를 보닛 곡률 방향으로 정렬, 또는 정수리 기준 행 거리장). 염색 경계가 "한 코씩" 뒤집히는 데 사용.
5. 출력: 각 사진 1x/2x WebP(덱 썸네일은 작게), 마스크·셀 맵은 1채널 PNG/WebP.

## 4. 스토리보드 (모바일 390×844 기준)

### S0 인트로 (≤ 900ms, 세션당 1회, 즉시 조작 가능)
- 0ms: 첫 사진(ivory front)이 **즉시** 표시(정적 `<img>`, LCP). 보닛 영역만 회색 실루엣(마스크) 상태.
- 120–820ms: 정수리부터 스캘럽 행 순서로 코가 채워지며 아이보리로 "떠짐"(행 간격 35ms, cubic-bezier(.2,.8,.2,1)). 동시에 화면 하단에서 실 한 가닥이 그려져 색 레일(5개 실타래)로 감김.
- 첫 입력 시 120ms 내 최종 상태로 점프, 입력은 원래 동작으로 전달.

### S1 덱 휴지 상태
- 단일 스테이지(사진 4:5, 화면 폭 ~88%, 둥근 모서리) + 하단 **색 레일**(5개 실타래 버튼; 현재 색에서 실 한 가닥이 사진 프레임으로 이어짐).
- 휴지 모션은 하나만: 4초 주기로 보닛 마스크 안에서만 섬유 쉬머 하이라이트가 지나감.
- 배경: 현재 실 색의 저채도 톤(정적, 전환 시에만 움직임). 포인터 패럴랙스는 배경 레이어 ≤ 6px(데스크톱만).

### S2 스와이프 = Live Dye (핵심 시그니처)
- 가로 드래그 진행도 p = dx/폭, **첫 픽셀부터 1:1**(slop 넘는 순간 그동안의 이동도 반영 — v1의 시작좌표 리셋 버그 금지).
- 염색 경계: 손가락 x 위치에서 시작해 셀 맵을 따라 **한 코씩** 다음 색으로 뒤집힘(셀별 임계값 = 거리장 + 셀 노이즈). 경계 코에는 아주 얇은 밝은 테두리(실 하이라이트). 얼굴·배경·옷은 1px도 안 움직임.
- 사진 프레임 바깥: 색 레일의 실 가닥이 다음 실타래로 당겨지며 팽팽해짐(장력은 실에만).
- 커밋: 속도 > 0.3px/ms 또는 p > 0.5 → 다음 색, 임계 감쇠에 가까운 스프링(오버슈트 없음). 강한 플릭도 1장(5개뿐이므로 2장 건너뛰기 없음 — 검토 대상).
- 버튼/레일 탭/키: 같은 p를 0→1로 **220ms** easeOutExpo, 레일 탭은 탭한 실타래 방향에서 염색 시작. 연타는 큐 없이 남은 진행 즉시 완료 후 다음 시작.
- 각도는 그대로 유지(현재 각도 사진 위에서 재염색).

### S3 덱 → 상세 (대표 연출, ~600ms, 가역)
- 0–80ms: 탭 다운 시 사진 scale 0.985 프레스.
- 80–360ms: 사진 rect가 덱 슬롯 → 상세 히어로 앵커 rect로 확장(모서리 28→0, affine만). 동시에 **프레임의 실이 풀려 굵은 실 몇 가닥이 화면 밖까지 뻗음**(GL 라인, 깊이·가림·그림자). 
- 300–560ms: 그 실들이 히어로 **뒤 배경**에서 거대한 쉘 스티치 구조(스캘럽 행 패턴)를 짜며 정착 → 상세 배경 텍스처가 됨(스케일 반전). 보닛 마스크엔 섬유 하이라이트 1회 스윕.
- 200–480ms: 제목 DOM FLIP, 본문 줄 단위 리빌(stagger 40ms). **본문은 나타나는 즉시 스크롤 가능**(애니메이션 완료를 기다리지 않음).
- 핸드오프: 사진 rect가 앵커에 도달하는 순간 GL 사진 → DOM `<img>`(동일 크롭/rect) 교체, 이후 GL은 배경 구조 정착만 마무리하고 휴면.
- 도중 Back/탭: 현재 상태에서 역방향 스프링.

### S4 상세 (DOM, window 네이티브 스크롤)
- 히어로: DOM `<img>`. 스크롤에 따른 연출은 CSS(transform)만.
- **색 변경 = Live Dye 재사용**: 스와치 탭 → 히어로 위에 GL 레이어를 잠깐 띄워 탭 방향에서 한 코씩 재염색(450ms) → 끝나면 DOM `<img>` 교체 후 GL 해제. 스크롤 중이면 히어로가 화면에 보일 때만 GL, 아니면 즉시 교체.
- **각도**: 썸네일/점/가로 스와이프(히어로에서만, `touch-action: pan-y pinch-zoom`)로 선명한 방향성 와이프 교체(180ms).
- **보닛 리프트(매크로)**: 히어로 보닛 탭 → 마스크 영역만 확대 루페(섬유 디테일, 업스케일 원본), 얼굴은 디밍만. 다시 탭/Esc로 해제.
- 섹션(소재·사이즈·관리)은 SVG stroke 라인 드로잉 하나만. 스크롤 진행 실은 생략(경쟁 방지).

### S5 상세 → 덱 (≤ 400ms)
- 닫기 버튼/Esc/Back. 스크롤 위치를 위로 강제 이동하지 않음.
- 히어로가 보이면: 현재 화면의 히어로 rect에서 GL 사진 스폰 → 덱 슬롯으로 수축(모서리 0→28), 배경 쉘 스티치 구조가 실 몇 가닥으로 감겨 색 레일로 회수.
- 히어로가 화면 밖이면: 본문 페이드 + 덱 사진이 제자리에서 페이드-스케일 인(짧은 대체 경로).
- 색이 바뀌었으면 이미 그 색으로 덱 복귀.

### S6 마이크로
- 버튼 프레스 scale 0.96/80ms, 복원 120ms. 큰 장력 해소는 S2 커밋에만.

### S7 Inspect 미니 모드 (M3 이후)
- 토글 시: 마스크(파란 오버레이), 코 셀 맵, 염색 진행도 p, 셀 임계값을 단계적으로 보여줌. 메인 사이트 Inspect와 같은 시각 언어.

## 5. 아키텍처 & 입력 규칙
- 렌더러: **raw WebGL2**(메인 사이트 `src/gl/renderer.ts`의 휴면/visibility/context 루프 패턴 참고, 하위 프로젝트에 복사). 단일 패스 프래그먼트 중심(사진·다음 색 사진·마스크·셀 맵 4 텍스처).
- 캔버스 `pointer-events: none`, `lvh` 기준 고정 크기, DPR ≤ 2, context lost → 즉시 DOM 사진 폴백.
- 상태 분리: 페이지 전환 / 덱 색 / 각도 / 색 전환 진행 — 각각 독립 상태. 애니메이션 완료가 버튼 활성화·스크롤 허용의 조건이 되면 안 됨.
- 입력:
  - 버튼은 `<button>` click 하나로. **전역 클릭 차단 금지**(ghost click 억제는 해당 드래그에서 생긴 그 요소의 click 1회만).
  - 제스처 면에 사전 `touch-action: pan-y pinch-zoom`, 버튼에서 시작한 입력은 제스처에서 제외, 본문 `touchmove.preventDefault()` 금지.
  - `pointercancel`/`lostpointercapture`/visibilitychange에서 드래그 정리.
- 텍스처 수명: 처음엔 현재 각도 front 5색(덱) + 마스크만. 상세 진입 시 해당 색 4각도 지연 업로드. 사용 끝난 ImageBitmap close.
- 폴백(GL 불가/reduced-motion): 같은 UI, 색 전환은 크로스페이드 + 마스크 기반 CSS `mask-image` 와이프(가능 시).

## 6. 검증 (v1 실패 재발 방지)
- **M0 게이트**: 효과 없는 버전(DOM만)으로 iPhone 실기기에서 원본(v20.0.15)과 나란히 비교 — 첫 반응·플릭·연속 버튼·상세 스크롤·Back 모두 원본 이상.
- 실기기 시나리오(매 마일스톤): 스와이프 직후 50/100/200ms에 버튼 탭, 대각선 미세 이동 후 탭, 빠른 방향 반전, 열기 도중 스크롤, 히어로/본문 각각에서 스크롤 시작, 관성 스크롤 중 색 변경, 주소창 확장/축소, 회전, 핀치줌, Back/Forward, 잠금 후 복귀, 5–10분 반복.
- `?debug` 오버레이: fps, 33ms 초과 프레임 비율, 최장 멈춤, 입력→첫 시각 반응 ms, 이벤트 로그. 실기기 화면 녹화로 제출.
- 자동 테스트는 보조: 실제 스크롤은 `scrollTop` 직접 설정이 아닌 터치 스와이프로 검증, 가상 타임스탬프 의존 금지.
- 얼굴 QA 체크리스트(최대값 프레임).

## 7. 마일스톤
- **M0** 자산 파이프라인(정합·업스케일·마스크·셀 맵) + DOM 전용 골격(덱/레일/버튼/상세/스크롤/Back) → iPhone 원본 비교 게이트.
- **M1** Live Dye 스와이프(S2) + 버튼/레일 + 폴백 → iPhone 게이트 + 영상.
- **M2** S3/S5 전환(실 구조 스케일 반전) + DOM 핸드오프 → iPhone 게이트 + 영상.
- **M3** S4(색 변경 Live Dye, 각도 와이프, 보닛 리프트) + S0 인트로 → iPhone 게이트.
- **M4** S7 Inspect 미니 + 성능/접근성 패스 → 배포.

## 8. 남은 질문 (2라운드에서 판단 요청)
1. 정합·업스케일 후 625→1122 업스케일 품질이 히어로 크기에서 충분한가? 아니면 히어로 크기를 줄이는 레이아웃이 나은가?
2. 마스크를 각도당 1장으로 공유할 수 있을 만큼 5색 정합이 정확할 것인가(보닛 실루엣 자체가 색마다 미세하게 다를 수 있음)?
3. S3 "실 구조 스케일 반전"을 raw WebGL2로 모바일 60fps에 구현할 현실적 방법(라인 수, 굵기, 셰이딩 방식).
4. 강한 플릭 2장 건너뛰기 유지 여부.
5. 이 계획이 "그 무엇보다 화려하고 자극적"이라는 소유자 기준을 충족하는가 — 점수와 마지막 한 수.
