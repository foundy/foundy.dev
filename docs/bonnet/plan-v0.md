# bonnet v2 — 컨셉 & 스토리보드 계획 (초안 v0)

> 2026-10-09 · 작성: Claude(Opus) · 검토 예정: 2라운드(Codex + 독립 서브에이전트)

## 0. 왜 다시 하는가 (v1 회고)
사용자 실기기 피드백(v1, PR #12 브랜치):
1. 덱 넘김 속도가 느림 — 원본 프로토타입보다 둔함.
2. 스와이프 버튼(←/→)이 실기기에서 동작하지 않음.
3. 상세 화면 스크롤이 안 됨.
4. 무엇보다 **평범함** — 메인 사이트(foundy.dev: 셰이더 히어로 + Inspect)에 비해 인터랙션이 초라함.

근본 원인:
- DOM transform만으로 "앱 같은 카드"를 재현하는 데 그침 → 시각적 놀라움이 없음.
- 검증이 Playwright 에뮬레이션(CDP 가상 터치)에만 의존 → 실기기 iOS의 pointer/touch/scroll 상호작용 버그를 못 잡음. 자동 테스트 125/125 통과했는데 실기기에서 기본 동작이 깨짐.
- 제스처 코드가 스크롤 컨테이너와 경쟁(touch preventDefault/claim)하면서 네이티브 스크롤을 죽임.

## 2. 컨셉: "Stitch" — 실로 짜이고 풀리는 쇼케이스
보닛은 **코바늘 쉘 스티치(scalloped shell stitch)** 로 뜬 제품. 모든 전환·피드백을 "실·뜨개·염색"의 물성으로 번역한다.
- **뜨기(knit)**: 이미지가 쉘 스티치 패턴 마스크를 따라 한 코씩 떠지며 나타남.
- **풀기(unravel)**: 사라질 때 한 줄씩 실로 풀려나감(실 가닥 파티클).
- **염색(dye)**: 색상 전환은 실이 염료를 빨아들이듯 섬유 방향 노이즈를 따라 번짐.
- **장력(tension)**: 드래그 속도 = 실의 장력 → 카드가 늘어나고 휘고, 놓으면 탄성 복원.
톤: 따뜻한 크림·린넨 바탕, 사진은 크게, 타이포는 세리프 디스플레이. 화려함은 GPU 레이어에서, 정보는 DOM에서.

## 3. 아키텍처 원칙
- **Persistent WebGL stage**: 화면 전체를 덮는 단일 캔버스(OGL 또는 raw WebGL2, 검토 대상). 모든 제품 이미지는 GPU 텍스처 평면. DOM에는 투명한 "앵커" 요소만 두고(접근성·레이아웃·클릭 타깃), 캔버스가 앵커 rect를 매 프레임 추적해 그 위치에 그림.
- **스크롤은 100% 네이티브**: 상세는 일반 문서 스크롤(window scroll). 제스처 코드가 스크롤을 가로채지 않음. 풀다운 닫기는 "최상단에서 overscroll"만 감지(iOS 러버밴드와 공존 방식은 검토 대상).
- **버튼/키보드는 제스처와 독립된 1급 경로**: `<button>` click → 같은 스프링 타깃. 제스처 레이어가 click을 삼키지 않음.
- **덱 응답성**: 1:1 추적 + 플릭 투영 τ를 원본 수준 이상으로(빠름). 실측 튜닝.
- **폴백**: WebGL 불가/저전력/reduced-motion → DOM 이미지 + CSS 크로스페이드(기능 동일).
- **실기기 검증 게이트**: 각 마일스톤마다 사용자 iPhone 확인을 통과 기준에 포함. 에뮬레이션 통과는 필요조건일 뿐.

## 4. 스토리보드 (모바일 390×844 기준, 데스크톱은 확장)

### S0. 인트로 (0–1.6s, 1회)
- 0.0s 크림 배경, 중앙에 한 가닥 실(SVG 패스 or GL 라인)이 "bonnet" 필기체 워드마크를 그림(0.9s).
- 0.9s 실 끝이 아래로 떨어지며 5장의 카드가 쉘 스티치 마스크로 **떠지며** 부채꼴로 착지(stagger 80ms, 스프링 오버슈트).
- 탭/스크롤/키 입력 시 즉시 스킵.

### S1. 덱 (휴지 상태)
- 3D 곡면 캐러셀: 앞 카드 정면, 좌우 카드는 원통 곡면을 따라 뒤로 휘어짐(실제 평면 곡률 셰이더).
- 배경: 현재 카드 색의 염료가 천천히 흐르는 섬유 노이즈 필드(저채도). 
- 아이들 모션: 앞 카드가 아주 미세하게 숨쉬기(scale 1.0↔1.006), 자이로(허용 시)/포인터로 2.5D 패럴랙스.
- 포인터 호버/터치 홀드: 사진 표면에 뜨개 질감 리플(flowmap) — 손가락이 지나간 곳이 짜임처럼 일렁임.

### S2. 덱 스와이프
- 손가락 1:1. 속도 → 장력: 카드가 이동 방향으로 늘어나고(스트레치), 곡률 증가, 가장자리에 실 올 풀림 디테일(속도 높을 때만).
- 배경 염료가 다음 카드 색으로 **액체처럼 번짐**(스와이프 진행도에 비례, 되돌리면 되돌아감).
- 놓으면 속도 투영으로 1~2장 이동, 스프링 안착, 장력 해소 시 탄성 진동 1회.
- ←/→ 버튼, 키보드, 점 = 같은 경로(빠른 애니메이션 260–320ms).

### S3. 덱 → 상세 (탭, 0.65–0.8s)
- 탭한 카드 평면이 화면 상단 히어로 영역으로 **끊김 없이 확장**(같은 GL 평면이 rect 보간, 모서리 반경 셰이더로 감소).
- 동시에 나머지 카드는 실로 **풀려** 흩어짐(평면을 가로 스트립으로 나눠 실 파티클로 해체, 0.4s).
- 배경 염료가 짙어지며 상세 배경 톤으로 정착.
- 제목: 카드 하단 타이틀이 상세 헤더 위치로 FLIP(DOM 텍스트, 마지막에 선명), 본문 줄 단위 마스크 리빌(stagger 40ms).
- 전 과정 하나의 progress p(0→1) 함수. 도중 탭/드래그 시 즉시 반전 가능.

### S4. 상세 (스크롤)
- 네이티브 스크롤. 히어로는 스크롤에 따라 살짝 줌아웃+블러 없음+색 테두리 생김(GL), 제목 고정 축소 헤더.
- 히어로 **앵글 뷰**: 가로 드래그로 4각도(정면→우→뒤→좌) 회전 — 단순 크로스페이드 대신 깊이맵 기반 2.5D 회전 착시(빌드 타임 깊이맵 생성, 검토 대상) 또는 방향성 디스플레이스먼트 와이프.
- **색상 스와치 탭 = 염색(dye) 전환**: 탭한 스와치 위치에서 새 색 사진이 섬유 노이즈를 따라 번져 히어로를 덮음(0.7s). 배경 톤 동시 전환.
- 섹션(소재/사이즈/관리)은 스크롤 진입 시 쉘 스티치 라인 드로잉 일러스트와 함께 등장.
- 스크롤 진행 표시: 화면 가장자리에 실 한 가닥이 스크롤만큼 떠짐.

### S5. 상세 → 덱 (닫기)
- 닫기 버튼/Esc/Back: S3 역재생 + 흩어졌던 카드들이 실에서 다시 **떠지며** 덱 복귀, 히어로는 원래 카드 슬롯(색 바뀌었으면 그 색 카드)으로 수축.
- 최상단에서 아래로 당김: 히어로가 손가락 따라 축소(p 스크럽), 놓으면 투영 판정. (iOS 러버밴드와 충돌 방지 방법은 검토 대상)

### S6. 마이크로 인터랙션
- 버튼 프레스: 실이 당겨지는 듯한 눌림 + 놓을 때 탄성.
- 햅틱(지원 기기): 카드 안착, 스와치 전환 시 아주 약하게.
- 사운드: 기본 off(토글 시 실 튕기는 미세음).

## 5. 기술 후보 (검토 대상)
- 렌더러: **OGL**(~25KB gz, 평면/텍스처/포스트 편함) vs raw WebGL2(메인 사이트 방식, 최소 용량) vs three(무거움).
- 실 풀림 효과: 인스턴스드 스트립(평면을 N개 가로 스트립 인스턴스로 그리고 정점 셰이더로 흩뿌림).
- 쉘 스티치 마스크: 절차적 SDF(반원 스캘럽 타일링)로 코 하나하나가 순차 리빌.
- 염색 전환: 섬유 방향 이방성 노이즈 + 스와치 위치 기준 거리장.
- 깊이맵: 빌드 타임에 오프라인 모델(Depth Anything 등)로 20장 생성해 커밋 vs 생략.
- 이미지: 1x/2x WebP, GPU 업로드 시 디코드 비동기(createImageBitmap).

## 6. 품질/검증 기준
- iPhone(최신 Safari) 실기기: 덱 스와이프 응답 지연 체감 0, 60fps 유지, 버튼·스크롤·Back 100% 동작.
- 초기 로드: 첫 덱 표시 ≤ 1.5s(4G), JS ≤ 60KB gz(GL 포함).
- 폴백 경로 기능 동일. reduced-motion 존중.
- 매 마일스톤: 에뮬레이션 테스트 + **사용자 실기기 체크(필수 게이트)** + 녹화 영상.

## 7. 마일스톤
1. M1 GL 스테이지 + 덱(S1, S2) + 버튼/키 + 폴백 → 실기기 체크
2. M2 덱↔상세 전환(S3, S5) + 네이티브 스크롤 상세 → 실기기 체크
3. M3 상세 인터랙션(S4: 앵글, 염색, 스크롤 연출) → 실기기 체크
4. M4 인트로(S0), 마이크로(S6), 성능/접근성 패스 → 배포
